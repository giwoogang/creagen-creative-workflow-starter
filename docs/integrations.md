# 도구 연결 안내

## 공통 방식

분석과 프롬프트 작성은 로컬 파일로 이어갑니다. 외부 서비스가 연결되어 있으면 실제 자료와 결과를 가져오고, 연결되지 않았으면 examples/의 샘플로 문서 실습을 진행합니다.

웹앱은 AdCatch 검색 요청과 결과를 주고받는 로컬 연결을 제공합니다. 실제 검색과 인증은 같은 프로젝트를 연 Codex 또는 Claude Code에 연결된 MCP 도구가 담당합니다. 웹앱에서 MCP를 직접 호출하거나 서비스 키를 입력하지 않습니다. 이미지 자동 생성 실행 모듈은 아직 연결되지 않았습니다. 영상은 로컬 제작 패키지 준비만 진행하고 실제 생성 서비스의 연결, 조회, 업로드, 견적과 생성은 별도 실행 시험 전까지 호출하지 않습니다.

## Codex와 Claude Code

**Claude Code에 Creagen(AdCatch 포함)을 연결하는 한국어 안내는 [Claude Code에 Creagen 연결하기](mcp-setup.md)에 있습니다.** 처음이라면 그 문서부터 따라 하세요. 아래는 전체 순서입니다.

1. 사용하는 도구에서 이 프로젝트 폴더를 엽니다.
2. README의 시작 문장을 입력합니다.
3. AGENTS.md의 공통 규칙을 읽었는지 확인합니다. Claude Code에는 같은 파일을 읽도록 안내하는 CLAUDE.md도 있습니다.
4. 참고 광고 검색에 사용할 MCP 또는 플러그인의 연결 안내를 따릅니다. 이번 영상 준비를 위해 생성 서비스를 새로 연결하지 않습니다.
5. AdCatch 검색 도구와 인증 상태를 확인합니다. 다른 사용자의 연결 상태를 그대로 가정하지 않습니다. 영상 생성 서비스의 연결 확인이나 모델 조회는 진행하지 않습니다.

도구별 설정 위치와 지원 방식은 공식 문서를 따릅니다. Claude 문서는 한국어판이 있습니다.

## AdCatch

웹앱의 2단계 **참고 광고**에서 원하는 광고를 찾고 선택합니다. 연결과 결과 가져오기의 세부 계약은 [AdCatch 안내](adcatch.md)에 있습니다.

1. “마미케어 광고”, “틱톡에서 지금 핫한 광고”, “틱톡 UGC” 예시 버튼을 누르거나 검색어를 적고 광고 유형과 플랫폼을 선택합니다. 플랫폼은 전체 플랫폼/TikTok/Meta입니다. 예시 버튼은 각각 brand/trending/ugc 의도를 저장하며 검색어를 직접 수정하면 general이 됩니다.
2. **검색 요청 만들기** → **검색 요청문 복사**를 누르고 같은 프로젝트의 Codex 또는 Claude Code 대화창에 붙여 넣습니다. 웹앱 서버는 계속 실행해 둡니다.
3. AI는 현재 연결된 도구의 스키마를 확인하고 실제 접근 가능한 작업 공간과 브랜드를 조회합니다. 계정과 권한은 이 AI 도구에 연결된 인증을 사용합니다.
4. 검색 조건에 맞는 실제 광고를 조회하고 최대 6개 후보를 고릅니다. 각 후보에 광고 ID, 출처, 확인한 자료와 추천 이유를 붙입니다.
5. AI는 [AdCatch 안내](adcatch.md)에 정해진 로컬 API로 후보를 가져옵니다. 실제 검색으로 확인하지 않은 광고나 관찰 내용을 만들지 않습니다.
6. 웹앱의 자동 갱신을 기다리거나 **검색 결과 새로고침**을 누릅니다. 사용자가 후보를 최대 3개 고르고 **선택한 광고 사용**을 누르면 제작 단계로 이어집니다.

현재 연결에서 확인되는 기본 도구 이름은 다음과 같습니다. 설치 환경에 따라 접두사가 달라질 수 있으므로 실제 호출에는 노출된 이름과 스키마를 사용합니다.

| 도구 | 확인할 내용 |
|---|---|
| `adcatch_list_workspaces` | 접근 가능한 작업 공간과 ID |
| `adcatch_list_brands` | 선택한 작업 공간의 브랜드와 ID |
| `adcatch_search_ads` | 이미 확보된 광고 중 조건에 맞는 후보 |
| `adcatch_get_ad` | 반환된 광고 ID의 상세 자료와 출처 |

AdCatch 도구는 Creagen 커넥터에 포함되어 있습니다. AdCatch를 따로 연결하지 않고 [Creagen 연결](mcp-setup.md)만 하면 됩니다. 다른 사용자의 연결 상태를 가정하지 않습니다. 연결이나 인증이 없으면 필요한 연결을 안내하고, **참고 광고 없이 계속** 또는 직접 등록한 참고 사진으로 실습을 이어갑니다. 이때 실제 검색이 완료된 것처럼 표시하거나 가짜 후보를 제공하지 않습니다.

검색은 AdCatch에 수집된 광고를 대상으로 합니다. TikTok 전체의 실시간 인기 검색이나 새 분석 생성이 아닙니다. “핫한 광고”는 응답에서 확인할 수 있는 관찰 신호를 참고할 후보로 설명합니다. 지정한 매체의 결과가 없으면 없다고 표시하며 다른 매체로 대체하지 않습니다. UGC 키워드가 일치했다는 이유만으로 UGC 형식이라고 판단하지 않습니다. 실제 영상이나 저장된 분석에서 형식의 근거를 확인합니다. 저장된 분석이 없으면 없는 상태로 남깁니다. 썸네일은 원본 영상 분석이 아니며, 영상에 접근하지 못했다면 장면, 움직임과 대사를 추측하지 않습니다. 집행 기간이나 변형 수는 관찰 신호이며 실제 매출이나 ROAS의 근거로 쓰지 않습니다.

선택한 광고 정보와 추천 이유는 제작 요청의 `context.references`에 담깁니다. 실제 광고 후보, 브랜드 정보와 검색 기록은 `work/`에 보관하고 공개 예시에 넣지 않습니다. API 키나 인증 토큰을 후보 자료와 요청문에 포함하지 않습니다.

## 영상 준비와 후속 실행

현재 영상 요청은 선택한 목표 길이, 비율과 스타일을 기준으로 `video-plan.json`과 `video-prompts.md`를 로컬에 저장합니다. 컷, 내러티브와 프롬프트 준비가 끝나도 영상 파일은 생성되지 않았습니다. 실제 동영상 생성은 미검증이며 이번 작업에서 생성 서비스의 MCP/API 연결 확인, 조회, 업로드, 견적과 생성을 호출하지 않습니다.

실제 생성은 사용자가 별도 실행 시험을 요청한 뒤 진행할 후속 작업입니다. 그때 모델 지원 조건과 비용, 생성 결과를 확인합니다. 지금 입력한 15/20/30초와 화면 비율은 제작 목표이며 모델 지원 보장이 아닙니다. 결과로 MP4/WebM 파일을 직접 등록할 수 있다는 사실도 실제 생성 성공을 뜻하지 않습니다.

## ZCRE: 별도로 요청된 실행에 사용할 순서

아래는 이미지 생성 등 별도로 요청된 실행의 참고 순서입니다. 현재 영상 준비에서는 실행하지 않습니다. 실제 모델 이름과 입력은 실행 시험 시 반환된 스키마를 사용합니다.

1. `query_zcre`의 `models`로 모델 목록을 확인합니다.
2. 선택한 모델을 `model`로 조회해 이미지 참조, 영상 길이 등 입력 규격을 확인합니다.
3. 파일을 업로드하고 업로드 확인 결과를 입력 참조에 연결합니다. 로컬 경로를 공개 URL처럼 넣지 않습니다.
4. `quote`로 입력 검증과 견적을 확인합니다.
5. 사용자가 요청한 범위와 실행 승인에 따라 `create_generation`을 호출합니다.
6. 반환된 요청 ID로 상태를 확인하고 완료 결과를 표시합니다.
7. 결과 파일과 모델, 입력, 실제 설정, 요청 ID, 생성 비용을 work/에 기록합니다. 서명 URL과 인증 토큰은 공개 문서에 쓰지 않습니다.

이 가이드는 호출 순서 초안이며, 저장소 자체에 생성 실행기가 구현되어 있다는 의미는 아닙니다. 견적만 조회한 단계와 실제 과금 생성 단계를 구분합니다. 응답 지연 때는 기존 요청 상태부터 확인합니다.

영상 모델은 현재 선택하거나 조회하지 않습니다. 이후 명시적인 실행 시험에서 지원 길이, 참조 수와 가격을 확인합니다. 4컷은 스토리보드 구분이며 API 호출 4번을 뜻하지 않습니다.

## Creagen

Creagen 커넥터 하나에 Creagen 생성 도구, AdCatch 광고 리서치 도구, AdAgent 광고 운영 도구가 함께 들어 있습니다. 연결 방법과 요금제는 [Claude Code에 Creagen 연결하기](mcp-setup.md)에 있습니다. 결제는 테스트 목적이라면 Creator 플랜을 추천합니다.

웹앱의 영상 준비 단계에서는 생성 도구 연결이나 업로드를 진행하지 않습니다. Claude 대화로 진행하는 [영상 재구성](video-remake.md)에서도 견적과 생성은 사용자가 실행 시험을 요청한 뒤에만 합니다. 이때 `creagen_get_generation_capabilities`로 입력 규격을, `creagen_estimate_credit`과 `creagen_get_credit_balance`로 견적과 잔액을 먼저 확인합니다. AdCatch 도구가 있다는 이유로 Creagen 생성까지 검증된 것으로 표시하지 않습니다. AdAgent의 캠페인 상태와 예산 변경 도구는 실제 집행에 영향을 주므로 명시적인 요청 없이는 쓰지 않습니다.

## Meta 성과

첫 실습은 examples/performance.sample.csv로 진행합니다. 내 브랜드에서는 같은 필드로 실제 성과를 내보내고 variant_id와 실제 광고 ID를 매핑합니다.

필수 확인 항목:

- 집행 기간과 집계 시점
- 통화
- 캠페인 목적, 타깃, 게재 위치와 비교 조건
- 클릭과 구매의 정의, 귀속 기준
- 비용, 노출, 클릭, 구매, 구매 전환값

첫 공개 범위는 성과 읽기와 다음 제작 가설까지입니다. 자동 업로드, 캠페인 게시, 예산 변경과 반복 운영은 실제 연결 검증 후 별도 확장합니다.

## 막혔을 때

| 상황 | 다음 행동 |
|---|---|
| AdCatch 연결 도구가 없음 | 같은 프로젝트를 연 AI 도구의 연결과 인증 상태 확인. 참고 광고 없이 또는 직접 준비한 사진으로 진행 |
| 검색 후보가 앱에 안 보임 | AI가 실제 검색과 로컬 API 등록을 끝냈는지 확인한 뒤 검색 결과 새로고침 |
| 요청 매체의 광고가 없음 | 해당 매체의 결과 없음으로 표시. 다른 매체로 자동 대체하지 않고 사용자가 조건을 바꾸게 안내 |
| UGC 형식의 근거가 없음 | 키워드 검색 결과만으로 단정하지 말고 실제 영상이나 저장된 분석에서 확인한 범위 표시 |
| 참고 영상 접근 불가 | 확인 가능한 대본이나 장면 설명을 사용하고 분석 범위를 표시 |
| 영상 패키지만 준비됨 | 정상적인 현재 완료 지점. 실제 생성은 별도 실행 시험에서 진행 |
| 별도로 요청된 이미지 생성의 입력 오류 | 현재 모델 스키마와 파일의 실제 규격 확인 |
| 별도로 요청된 이미지 생성 대기 또는 응답 없음 | 기존 요청 ID로 상태 확인. 새 요청을 반복하지 않음 |
| 결과에서 제품이나 인물 변경 | 입력 참조와 바뀐 부분을 기록하고 다음 수정 범위를 정함 |
| 성과 조건이 다름 | 수치 계산과 승자 판단을 구분. 비교할 수 없는 이유 기록 |
