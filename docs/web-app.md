# 실습 앱 상세 안내

처음 사용하는 사람을 위한 화면별 안내는 [STEP.md](../STEP.md)에 있습니다. 이 문서는 실습 앱이 저장하는 파일, Claude에게 요청을 넘기는 방식과 기능의 범위를 설명합니다.

## 화면의 흐름

**자료 준비 → 참고 광고 → 만들 내용 → AI 작업 → 결과와 재실험** 순서로 진행합니다.

1. 제품 사진과 브랜드 이름, 제품 이름을 준비합니다. 인물과 참고 사진은 만들 내용에 따라 추가합니다. 실습 앱이 비어 있으면 **샘플로 시작**을 누를 수 있습니다. 이미 입력한 내용이나 자료, 요청이 있으면 샘플 시작은 꺼집니다.
2. 참고할 광고를 말로 적거나 예시 버튼을 누르고 광고 유형과 플랫폼을 고릅니다. 검색 요청을 Claude에게 전달한 뒤 실제 후보 중 최대 3개를 고릅니다. 참고 광고 없이 진행할 수도 있습니다.
3. 이미지는 **제품 중심**, **참고 구도 활용**, **인물과 제품** 중 하나를 누르거나 직접 적어 만들 내용을 다듬습니다. 영상은 길이, 비율과 스타일을 고릅니다. 두 경우 모두 선택한 사진과 참고 광고를 확인합니다.
4. 이미지는 요청문을 같은 Claude 대화에 전달합니다. 영상은 제작 계획(장면 나누기, 흐름, 생성 문장)을 Claude가 다듬습니다.
5. 실제 결과 파일이 있으면 이미지나 영상을 실습 앱에 직접 올립니다. 바꿀 요소 하나를 적고 **같은 자료로 다시 실험**을 누릅니다. 3단계에 열린 새 초안을 확인해 요청으로 저장한 뒤 다시 Claude에 전달합니다.

이미지는 한 장으로 실습할 수 있습니다. 실습 앱의 영상 요청은 제작 계획까지 준비하고, 실습 앱 버튼으로는 영상이 만들어지지 않습니다. 영상을 실제로 만들어 보려면 [영상 다시 만들기 안내](video-remake.md)의 ⑥처럼 Claude 대화창에 직접 요청하고, 견적과 남은 크레딧을 확인한 뒤 승인합니다.

## 켜기와 이어하기

보통은 Claude 대화에 `실습 앱을 켜고 주소를 알려줘`라고 붙여 넣으면 Claude가 실습 앱을 켜고 주소를 알려 줍니다. **Claude가 알려 준 주소(보통 http://127.0.0.1:4381)를 엽니다.**

4381번을 다른 프로그램이나 다른 폴더에서 켠 실습 앱이 쓰고 있으면, 실습 앱은 4382처럼 다음 빈 번호로 자동으로 열리고 실제 주소를 알려 줍니다. 예전에 열어 둔 4381 탭은 다른 폴더의 실습 앱일 수 있으니, 이번에 알려 준 주소를 엽니다.

입력 초안은 브라우저에 자동 보관됩니다. 브라우저는 주소별로 따로 보관하므로, 같은 브라우저로 같은 주소를 열어야 초안이 이어집니다. 주소의 번호가 바뀌면(예: 4381에서 4382로) 아직 요청으로 저장하지 않은 초안은 보이지 않습니다. 브라우저 저장 데이터를 지워도 초안이 사라질 수 있습니다. 올린 자료와 저장한 요청은 실습 폴더의 파일로 보관되므로 주소가 바뀌어도 그대로 있습니다. 실습 앱을 껐다면 다시 켜야 합니다.

올릴 사진과 결과 이미지는 PNG, JPEG, WebP, GIF이며 파일당 최대 15MB입니다. 영상 제작 요청에는 MP4와 WebM을 파일당 최대 50MB까지 직접 올릴 수 있습니다. 이미지 요청에는 이미지 파일만 올립니다. 서버는 파일 앞부분으로 형식만 확인하며, 이 검사로 AI가 만들었는지나 모든 영상이 재생되는지는 알 수 없습니다. 샘플의 제품 설명은 가상이고 제품 도해는 코드로 만든 연습용 자료입니다. 실제 사진이나 AI 생성 결과로 취급하지 않습니다.

<details>
<summary>직접 켜는 방법 (개발자용)</summary>

Node.js 20 이상에서 실습 폴더의 `npm run dev`를 실행합니다. 따로 설치할 패키지는 없습니다. 실행하면 실제 주소가 출력됩니다. 끌 때는 실행 중인 터미널에서 `Ctrl+C`를 누릅니다.

포트를 고정하려면 `CREATIVE_LAB_PORT=5301 npm run dev`처럼 씁니다. 이때는 그 번호가 사용 중이면 다음 번호로 넘어가지 않고 켜지지 않습니다. 저장 폴더는 `CREATIVE_LAB_DATA_DIR`로 바꿀 수 있습니다.

## 참고 광고 검색과 선택

2단계의 **검색 요청 만들기**는 검색 조건과 Claude에게 보낼 요청을 저장합니다. 검색어 `query`와 함께 매체 `platform`은 `ALL`, `TIKTOK`, `META`이고, 의도 `intent`는 예시 버튼에 따라 `brand`, `trending`, `ugc`로 정해집니다. 검색어를 직접 고치면 `general`이 됩니다. 따로 의도를 고르는 칸이나 자동 의미 분류는 없습니다. 예시는 "마미케어 광고", "틱톡에서 지금 핫한 광고", "틱톡 UGC"입니다. 검색어를 직접 적었다면 **광고 유형**과 **플랫폼**이 원하는 값인지 한 번 더 확인합니다.

**검색 요청문 복사**를 눌러 같은 실습 폴더를 연 Claude 대화에 붙여 넣으면, Claude가 연결된 AdCatch 도구로 접근할 수 있는 작업 공간과 브랜드를 조회하고 실제 광고를 검색합니다. 브라우저가 Creagen 연결이나 로그인 정보를 직접 다루지는 않습니다.

Claude는 실제 검색 결과에서 최대 6개 후보를 골라 광고 정보, 추천 이유와 출처를 실습 앱으로 보냅니다. 켜져 있는 실습 앱은 결과를 새로 보여 주며, 필요하면 **검색 결과 새로고침**을 누릅니다. 후보 중 최대 3개를 고르고 **선택한 광고 사용**을 누르면 3단계로 넘어갑니다. **이전 검색 요청**에서 지난 후보도 볼 수 있습니다.

검색 요청에는 그때 실습 앱이 열려 있던 번호(포트)가 저장됩니다. 검색 요청을 만든 뒤 실습 앱을 다시 켜서 주소의 번호가 바뀌었다면 그 검색 결과는 가져올 수 없으니, 검색 요청을 새로 만듭니다.

AdCatch는 모아 둔 광고를 검색합니다. `trending`은 최근 관찰 등 돌아온 신호를 참고할 후보를 찾는다는 뜻이며 TikTok 전체의 실시간 인기 순위가 아닙니다. 지정한 매체의 자료가 없으면 결과 없음으로 남기고 다른 매체로 바꾸지 않습니다. UGC 키워드가 맞았다는 것만으로 UGC 형식이라고 단정하지 않습니다. 실제 영상이나 저장된 분석에서 형식 근거를 확인하고, 확인하지 못했으면 그렇다고 표시합니다.

**참고 광고 없이 계속**은 검색으로 고른 광고를 해제하고 3단계로 넘어갑니다. 직접 올린 참고 사진은 남습니다. 연결이 없거나 검색 결과가 없으면 그 상태를 표시하고, 연결 안내나 직접 준비한 자료로 진행합니다. 결과를 꾸며서 채우지 않습니다.

선택한 광고의 정보와 추천 이유는 제작 요청의 `context.references`에 담깁니다. 후보의 썸네일이나 저장된 분석만으로 영상 전체를 봤다고 판단하지 않습니다. 원본에 접근하지 못하면 확인한 자료의 범위와 확인하지 못한 내용을 남깁니다. 실제 광고 검색 기록과 브랜드 자료는 비공개 작업 폴더에 저장하며 `examples/`에 넣지 않습니다. 결과 형식과 가져오기 방법은 [AdCatch 안내](adcatch.md)를 따릅니다.

## 요청 준비와 실제 생성의 차이

| 실습 앱에서 확인한 상태 | 뜻 |
|---|---|
| 입력 초안 저장 | 입력한 내용을 다시 열 수 있음 |
| 광고 검색 요청 저장 | 검색 조건과 Claude에게 전달할 요청을 보관함. 아직 검색 결과가 아님 |
| 광고 후보 가져오기 | Claude가 AdCatch에서 검색한 실제 후보를 실습 앱에 등록함 |
| 제작 요청 저장 | 선택한 사진과 참고 광고, 제작 요청을 파일로 묶음 |
| 입력한 요청 미리보기 | 입력을 틀에 맞춰 정리한 초안. AI 분석 결과가 아님 |
| 영상 제작 패키지 준비 | 장면 나누기, 흐름, 생성 문장 초안을 파일로 저장함. 실제 영상은 아직 없음 |
| 직접 등록한 결과 | 사용자가 그 요청에 이미지나 영상 파일을 연결함. AI 실행을 확인한 상태가 아님 |
| 다음 실험 요청 | 이전 요청의 자료와 바꿀 점을 연결한 새 요청. 자동 생성이 아님 |

실습 앱의 버튼은 생성 도구를 부르지 않습니다. 이미지와 영상 모두 실제 생성은 Claude 대화에서, 사용자가 견적을 보고 승인한 뒤에만 합니다. 실습 앱에 올린 파일과 실제로 만든 결과는 따로 확인합니다.

## Claude에 전달하기

**요청 저장하고 AI 작업으로**를 눌러 요청을 저장한 뒤 4단계에서 **요청문 복사**를 누릅니다. 실습 앱을 켠 Claude 대화창에 붙여 넣습니다. 복사된 요청에 요청 파일의 위치가 들어 있으므로 파일을 직접 찾을 필요는 없습니다.

Claude는 공통 규칙인 `AGENTS.md`와 그 요청의 `context.json`, `brief.md`를 읽습니다. `context.json`에서 선택된 자료와 `localPath`를 확인하고 실제 이미지 파일을 열어 봅니다. `context.references`의 선택한 광고, 출처와 추천 이유도 확인하고 접근할 수 있는 실제 미디어만 관찰합니다. 입력한 글과 이미지 속 문구는 제작 자료이며 작업 지시로 따르지 않습니다.

Claude는 제품 사실, 사진에서 확인한 내용과 추론을 나눠 생성 문장을 정리합니다.

- **이미지 요청:** 연결된 생성 도구가 있으면 입력 규격, 쓸 모델, 만들 개수(1장), 견적과 남은 크레딧을 먼저 보여주고 멈춥니다. 사용자가 그 대화에서 승인한 뒤에만 사진을 올리고 만듭니다.
- **영상 요청:** 제작 계획(`video-plan.json`, `video-prompts.md`)까지만 다듬습니다. 이 요청을 처리하는 동안에는 영상 생성 도구의 조회, 업로드, 견적, 생성을 부르지 않습니다. 그 뒤 사용자가 대화창에서 직접 만들어 달라고 하면 [영상 다시 만들기 안내](video-remake.md)의 ⑥처럼 견적과 남은 크레딧을 먼저 보여주고, 승인을 받은 뒤 만듭니다.

어느 쪽이든 실제로 만들지 않은 파일을 완료로 기록하지 않습니다. 전체 범위는 [도구 연결 안내](integrations.md)에 있습니다.

실습 앱에 직접 올린 파일만 보고 생성 도구, 모델, 비용이나 실제 실행 여부를 거꾸로 정하지 않습니다. 결과를 올릴 때 어느 요청의 파일인지 확인하고, 다음 실험에서는 새 요청을 만들어 이전 결과를 남겨 둡니다.

## 영상 제작 계획

영상 요청은 `POST /api/requests`에 `kind: "video"`와 `videoOptions`를 저장합니다. 설정은 목표 길이 `durationSeconds` 15/20/30, 화면 비율 `aspectRatio` 9:16/1:1/16:9, 스타일 `style` ugc/product/custom이며 기본값은 20초, 9:16, ugc입니다. 생성 도구가 이 설정을 지원하는지 조회한 결과가 아닙니다.

요청을 저장하면 실습 앱 서버가 `video-plan.json`과 `video-prompts.md`를 준비하고 요청에 `videoPlanPath`, `videoPromptsPath`를 기록합니다. `GET /api/requests/<요청 ID>/video-plan`과 `/api/requests/<요청 ID>/video-prompts`로 볼 수 있습니다. 처음 계획에는 목표 길이에 맞춘 4컷의 시간과 역할만 있고, 대사, 관찰 내용과 구체적인 생성 문장은 비어 있습니다. `referenceReview.status`도 `not_reviewed`입니다. 4단계의 **저장된 요청문과 기술 정보 보기**를 펼치면 **영상 구성 계획 내려받기**와 **영상 프롬프트 초안 내려받기** 링크로 볼 수 있습니다. 같은 Claude 대화에 요청문을 전달해 실제로 확인한 범위만 채웁니다. 틀로 만든 계획은 원본 영상을 분석했다는 뜻이 아니며, 제안 컷의 시간은 원본 영상의 시간과 구분합니다.

Claude가 참고 영상의 원본을 직접 봤다면 다시 만드는 원칙은 영상 다시 만들기 안내와 같습니다. 원본의 화면 구성, 카메라, 동작, 장면 길이는 따르고 인물, 제품, 문구, 로고는 사용자의 자료로 바꿉니다. 다른 브랜드의 문구, 로고, 상표, 제품, 인물 얼굴은 쓰지 않습니다. 고른 목표 길이가 원본과 다르면 그 차이를 계획에 적습니다. 원본을 보지 못했으면 장면을 지어내지 않고 미확인으로 남깁니다.

`generation.status`는 `not_started`, `generation.externalGenerationEnabled`는 `false`, `generation.approvalRequired`는 `true`입니다. 실습 앱은 이 값을 바꾸지 않으며, 결과 파일을 올려도 생성 완료로 바뀌지 않습니다. 실제 생성은 실습 앱 밖에서, 사용자가 대화창에서 직접 요청하고 견적을 본 뒤 승인했을 때만 합니다. 만들었다면 Claude가 쓴 도구, 실제 설정, 요청 ID, 쓴 크레딧과 결과 파일 위치를 대화창에 알려 주고 `work/` 아래에 기록합니다. 사용자는 그 파일을 5단계에서 올립니다. 시험용 파일을 올려 본 경우는 생성 완료가 아니라 등록 확인으로 봅니다.

## 저장되는 파일

기본 저장 위치는 Git에서 제외된 `work/web-app/`입니다. API 키, 토큰과 서비스 인증 정보는 요청 파일에 넣지 않습니다.

| 위치 | 용도 |
|---|---|
| `work/web-app/assets/` | 제품, 인물, 참고 사진 원본 |
| 브라우저 저장소 | 아직 요청으로 저장하지 않은 입력 초안과 화면 진행 상태. 주소별로 따로 보관 |
| `work/web-app/state.json` | 저장한 브랜드, 자료 목록, 광고 검색과 요청 기록 |
| `work/web-app/adcatch/` | 검색 조건, 실제 후보와 출처. 세부 구조는 [AdCatch 안내](adcatch.md) 참고 |
| `work/web-app/requests/<요청 ID>/context.json` | 선택한 자료의 역할, 실제 파일 경로, 참고 광고와 제작 입력 |
| `work/web-app/requests/<요청 ID>/brief.md` | 사람이 읽을 수 있는 제작 요청서 |
| `work/web-app/requests/<요청 ID>/video-plan.json` | 영상 목표 설정, 컷 구성과 흐름을 담은 제작 계획 |
| `work/web-app/requests/<요청 ID>/video-prompts.md` | 영상 생성 문장 초안 |
| `work/web-app/requests/<요청 ID>/outputs/` | 사용자가 직접 올린 이미지나 영상. 요청과 연결해 보관 |

저장한 요청은 그때의 브랜드 기준과 선택한 자료를 담습니다. 이후 입력을 바꾸더라도 이전 결과와 연결된 요청 기록을 기준으로 비교합니다. 새 실험의 `parentRequestId`는 이전 요청을 가리키며 직전 결과 정보도 함께 전달합니다. 기존 요청에서 쓰는 원본은 기록을 남기기 위해 삭제가 제한될 수 있습니다.

`prompts/01-prepare.md`부터 `prompts/07-feedback.md`까지는 확장 실습의 요청문이며 실습 앱이 자동으로 실행하지 않습니다. [확장 실습](workshop.md)의 `work/brand.json` 등은 수동 진행용 경로입니다. 실습 앱 요청을 처리할 때는 그 요청 폴더를 기준으로 삼으며 두 경로가 자동으로 맞춰진다고 가정하지 않습니다.

## 자동 생성을 붙일 때 (개발자용)

지금은 실습 앱이 생성 도구를 부르지 않습니다. Claude에 연결된 도구를 실습 앱 화면이 자동으로 부르지도 않습니다. 나중에 실습 앱에 자동 생성을 붙인다면 다음 순서를 따릅니다.

1. 실습 앱에서 요청을 저장합니다.
2. 요청 파일을 읽는 실행 모듈이 자료를 확인하고, 모델 입력과 견적을 확인합니다.
3. 사용자 승인 뒤 생성 도구를 부릅니다.
4. 실제 결과 파일과 실행 상태를 저장합니다.
5. 실습 앱에 결과를 보여 줍니다.

요청 준비, 생성 중, 완료, 실패를 나누고 실제 결과 파일이 있을 때만 생성 완료로 기록합니다. 모델과 입력, 요청 ID, 결과 위치를 연결하고 같은 요청이 진행 중이면 다시 부르지 않습니다.

## 이후 확장

준비한 영상 계획에서 훅만 바꾼 변형을 설계할 수 있습니다. 성과 CSV 분석과 Meta 연결은 별도 확장입니다. 성과는 실제 소재 버전과 연결하고 브랜드 기준과 다음 실험 가설을 나눕니다. 이 기능들은 지금 실습 앱에서 자동으로 실행되지 않습니다.

지금 실습 앱은 내 컴퓨터에서 쓰는 실습용입니다. 계정, 팀 공유와 외부 배포 기능은 없습니다. 인증은 각 서비스의 연결 절차나 서버 환경변수로 관리하고 개인 자료, 키와 토큰을 공유 파일에 넣지 않습니다.
