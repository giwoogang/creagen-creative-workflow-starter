# 확장 실습: 영상 구성과 성과 비교

**처음이라면 [STEP.md](../STEP.md)에서 이미지 요청 또는 영상 패키지 준비부터 해보세요.** 이 문서는 그다음에 Codex 또는 Claude Code와 대화하며 진행하는 7단계 확장 실습입니다. 제품 하나로 이미지 광고와 4컷 UGC 구성을 만들고, 훅이 다른 3안의 성과를 비교해 다음 실험 가설을 수정합니다.

웹앱은 자료 준비 → 참고 광고 → 만들 내용 → AI 작업 → 결과와 재실험의 5단계입니다. 아래 7단계는 확장 실습 순서이며 웹앱에서 자동 실행되지 않습니다. 프로젝트 폴더를 열고 [README](../README.md)와 [공통 규칙](../AGENTS.md)을 읽도록 요청하세요. 웹앱의 2단계에서는 “마미케어 광고”, “틱톡에서 지금 핫한 광고”, “틱톡 UGC” 예시로 AdCatch 검색을 요청하고 실제 후보를 고를 수 있습니다. 검색은 수집된 광고 범위이며 TikTok 전체의 실시간 인기 순위가 아닙니다. 요청한 플랫폼의 광고가 없으면 다른 플랫폼으로 대체하지 않습니다. 검색 방법은 [AdCatch 안내](adcatch.md)를 참고하세요. 이미 제작 요청을 저장했다면 해당 요청의 자료와 `context.references`에 선택된 광고를 먼저 사용합니다. 아래의 `work/brand.json` 같은 수동 실습 파일은 웹앱과 자동 동기화되지 않습니다.

## 실습 경로 고르기

- **샘플 모드:** `examples/`의 가상 브랜드, 텍스트 참고 자료와 CSV로 진행합니다. 웹앱의 샘플 시작에는 코드로 만든 제품 도해도 제공됩니다.
- **내 브랜드 모드:** 직접 준비한 제품, 인물, 참고 광고와 성과 자료로 진행합니다.

샘플의 제품 설명과 성과는 가상이며 제품 도해는 실제 제품 사진이나 AI 생성 결과가 아닙니다. 참고 영상과 자동 생성 연결은 포함하지 않습니다. 샘플 모드는 분석 초안, 프롬프트, 제작 계획과 성과 피드백까지 진행하고, 실제 생성하지 않은 항목은 `pending`으로 남깁니다. 미디어 생성에는 해당 장면에 필요한 사진과 생성 서비스 연결이 필요합니다. 연결 방법과 지원 여부는 [도구 연결 안내](integrations.md)를 확인하세요. 웹앱에서는 결과 이미지와 MP4/WebM 파일을 직접 등록할 수 있습니다. 이것은 AI 생성 실행을 검증했다는 뜻이 아닙니다.

## 현재 영상 실습의 완료 범위

영상 요청은 목표 길이 15/20/30초, 비율 9:16/1:1/16:9, 스타일 UGC 사용 장면/제품 중심/직접 지정을 고른 뒤 로컬 패키지를 준비합니다. 별도 설정을 보내지 않을 때의 기본값은 20초, 9:16, UGC 사용 장면입니다. 화면에서는 선택한 참고 광고에 따라 스타일이 제안될 수 있으므로 저장 전에 확인합니다. 초기 `video-plan.json`은 4컷 시간과 역할을 제공하며 대사, 관찰 내용과 프롬프트는 확인 후 보완합니다. `video-prompts.md`와 함께 저장되며 특정 생성 모델의 지원을 검증한 설정은 아닙니다.

이번에는 영상 생성 서비스의 MCP/API 연결 확인, 모델 조회, 업로드, 견적과 생성을 호출하지 않습니다. 아래 영상 분석과 변형 설계도 준비 단계까지 진행합니다. 실제 동영상 생성은 미검증이며 사용자가 나중에 별도 실행 시험을 요청하면 그 범위를 확인합니다. 테스트용 파일로 결과 등록을 확인한 경우에도 실제 생성 완료로 기록하지 않습니다.

## 매 단계에서 확인할 것

- 입력과 결과는 `work/`에 저장합니다. 같은 이름의 파일이 있으면 먼저 내용을 확인합니다.
- 제품 사실, 직접 관찰한 내용, 추론, 실험 가설을 구분합니다.
- `reference_id`와 `variant_id`는 분석부터 성과 비교까지 같은 값을 사용합니다.
- 결과를 저장한 뒤 입력 파일, 출력 파일, 다음 단계, 막힌 항목을 짧게 보고받습니다.
- 파일이 만들어졌다는 것과 이미지나 영상이 생성됐다는 것을 구분합니다.

## 01. 제품과 인물 준비

**입력:** `examples/brand.example.json`, `examples/assets.example.json`, `rules/creative-rules.md`.
내 브랜드로 진행한다면 제품 설명과 사용할 제품 및 인물 파일을 추가합니다.

**붙여 넣을 요청:** [에셋 준비 프롬프트](../prompts/01-prepare.md)

```text
prompts/01-prepare.md를 읽고 1단계를 진행해줘.
모드를 지정하지 않았다면 샘플 모드로 시작해줘.
샘플 브랜드와 에셋 목록, 기본 제작 규칙을 확인하고
work/brand.json, work/assets.json, work/creative-rules.md를 준비해줘.
실제 미디어가 없는 항목과 추가로 필요한 자료를 표시해줘.
```

**완료 기준**

- 제품 이름, 대상 고객, 확인된 제품 사실과 사용할 수 없는 표현이 구분되어 있습니다.
- 에셋 목록에서 실제 파일이 있는지 확인할 수 있습니다. 없는 파일 경로는 만들지 않습니다.
- `work/creative-rules.md`에 브랜드 고정 기준과 수정 가능한 실험 가설이 구분되어 있습니다.

**다음:** 준비한 제품을 기준으로 02단계에서 참고 소재를 기록합니다.

## 02. 참고 소재와 출처 기록

**입력:** `work/brand.json`, `examples/references.example.json`.
내 브랜드 모드에서는 AdCatch로 수집한 자료나 직접 확보한 광고 자료를 사용합니다.
링크만으로 내용을 확인할 수 없다면 화면, 대본 또는 영상 파일이 필요합니다.

**붙여 넣을 요청:** [참고 자료 프롬프트](../prompts/02-reference.md)

```text
prompts/02-reference.md를 읽고 2단계를 진행해줘.
브랜드 정보와 확보한 참고 자료를 정리해서 work/references.json에 저장해줘.
각 자료의 reference_id, 출처, 확보한 자료의 종류와 확인하지 못한 부분을 남겨줘.
샘플 텍스트는 가상 설명으로 표시하고 실제 광고를 본 것처럼 기록하지 말아줘.
```

**완료 기준**

- 모든 참고 자료에 `reference_id`와 출처 또는 샘플 표시가 있습니다.
- 링크, 이미지, 영상, 대본 중 무엇을 확보했는지 확인할 수 있습니다.
- 이미지 구성과 영상 분석에 사용할 참고 자료를 골랐습니다.

**다음:** 03단계에서 참고 소재의 설득 구조를 자사 이미지 광고로 바꿉니다.

## 03. 이미지 광고 구성과 프롬프트

**입력:** `work/brand.json`, `work/assets.json`, `work/references.json`, `work/creative-rules.md`.
실제 참고 이미지가 없다면 제공된 설명을 바탕으로 작성한 구성안임을 표시합니다.

**붙여 넣을 요청:** [이미지 제작 프롬프트](../prompts/03-image.md)

```text
prompts/03-image.md를 읽고 3단계를 진행해줘.
참고 자료의 훅, 문제, 제품 역할, 근거와 CTA를 work/narrative-image.md에 정리해줘.
우리 제품 사실과 에셋에 맞춘 이미지 프롬프트를 work/image-prompts.md에 작성해줘.
실제 이미지가 없다면 관찰 결과 대신 텍스트 기반 구성안이라고 표시해줘.
```

**완료 기준**

- `work/narrative-image.md`에서 참고한 표현의 설득 역할을 설명합니다.
- `work/image-prompts.md`에서 제품, 인물, 구도, 배경, 문구와 고정할 요소를 확인할 수 있습니다.
- 프롬프트가 확인되지 않은 효능이나 수치를 새로 만들지 않았습니다.
- 샘플 모드에서는 프롬프트 작성까지 완료하며, 생성된 이미지가 있다고 기록하지 않습니다.

**다음:** 04단계에서 영상의 시간 흐름과 컷별 역할을 분석합니다.

## 04. 참고 영상 분석

**입력:** `work/references.json`과 확보한 영상, 대본 또는 샘플 설명.
대본만 있다면 말의 흐름은 분석할 수 있지만 화면과 움직임은 확인할 수 없습니다. 웹앱 요청을 사용한다면 해당 `context.references`와 요청 폴더를 기준으로 진행합니다. UGC 여부는 단어 검색만으로 판단하지 않고 실제 영상이나 저장된 분석에서 확인합니다.

**붙여 넣을 요청:** [영상 분석 프롬프트](../prompts/04-analyze-video.md)

```text
prompts/04-analyze-video.md를 읽고 4단계를 진행해줘.
확보한 자료에서 확인 가능한 컷의 역할과 설득 흐름을 work/video-analysis.md에 정리해줘.
관찰한 사실, 설명에서 가져온 내용, 추론을 구분해줘.
보지 못한 장면, 표정, 움직임과 타임코드는 만들지 말아줘.
영상 생성 서비스의 연결, 조회, 업로드, 견적과 생성은 호출하지 마.
```

**완료 기준**

- `work/video-analysis.md`에 분석 대상의 `reference_id`가 있습니다.
- 훅, 문제 제시, 제품 등장, 근거, CTA 중 확인 가능한 역할이 정리되어 있습니다.
- 실제 영상 분석과 샘플 설명 분석이 구분되어 있습니다.
- 영상에서 확인하지 못한 부분은 빈칸 또는 확인 필요로 남겨 두었습니다.

**다음:** 05단계에서 확인한 설득 흐름을 자기 제품과 인물에 맞춥니다.

## 05. 자사 제품과 인물로 4컷 구성

**입력:** `work/brand.json`, `work/assets.json`, `work/video-analysis.md`, `work/creative-rules.md`.
참고 광고의 문구와 장면을 복제하지 않고, 각 컷의 역할을 자사 표현으로 작성합니다.

**붙여 넣을 요청:** [브랜드 적용 프롬프트](../prompts/05-adapt.md)

```text
prompts/05-adapt.md를 읽고 5단계를 진행해줘.
우리 제품과 인물에 맞춘 4컷 구성을 work/storyboard.md에 작성해줘.
각 컷의 역할, 화면, 대사 또는 자막, 제품 노출과 전환을 적어줘.
이를 바탕으로 work/video-prompts.md를 작성하고 필요한 에셋과 확인할 항목을 남겨줘.
웹앱 요청이면 해당 video-plan.json과 video-prompts.md를 보완해줘.
선택한 목표 길이와 비율을 유지하되 생성 모델의 지원을 보장하지 마.
영상 생성 서비스의 연결, 조회, 업로드, 견적과 생성은 호출하지 마.
```

**완료 기준**

- `work/storyboard.md`에 4개 컷과 각 컷의 목적이 있습니다.
- 제품과 인물의 일관성을 유지할 기준이 모든 컷에 적용됩니다.
- `work/video-prompts.md`에 사용할 에셋과 컷별 생성 요청이 연결되어 있습니다.
- 생성 서비스의 모델 이름이나 지원 옵션을 추측해 넣지 않았습니다.
- 웹앱 패키지의 생성 상태는 `not_started`이며 실제 영상 생성과 구분되어 있습니다.

**다음:** 06단계에서 첫 훅 하나만 바꾼 3안을 설계합니다.

## 06. 훅이 다른 영상 3안

**입력:** `work/storyboard.md`, `work/video-prompts.md`, `work/creative-rules.md`.
첫 실험에서는 제품, 인물, CTA와 영상 길이를 고정하고 첫 훅만 바꿉니다.
다시 진행할 때는 수정한 가설에 따라 비교할 요소를 정하고 새로운 변형 ID를 붙입니다.

**붙여 넣을 요청:** [변형 제작 프롬프트](../prompts/06-variants.md)

```text
prompts/06-variants.md를 읽고 6단계를 진행해줘.
첫 실험은 훅만 다른 3안, 다음 실험은 수정된 제작 규칙에 따른 3안을 제안해줘.
각각의 실험 가설을 work/variants.json에 저장하고 이전 결과는 보존해줘.
다음 실험에는 새 variant_id를 붙여 이전 성과와 구분해줘.
variant_id를 붙이고 work/video-prompts.md에 각 안의 프롬프트를 연결해줘.
work/generation-log.json에 실제 진행 상태를 기록해줘.
생성하지 않은 항목은 pending으로 두고 필요한 입력을 알려줘.
이번에는 영상 생성 도구를 호출하지 말고 계획과 프롬프트까지만 작성해줘.
```

**완료 기준**

- `work/variants.json`에 서로 다른 `variant_id`를 가진 3안이 있습니다.
- 어떤 변경이 어떤 반응을 기대하는지 설명하고, 고정할 요소를 명시합니다.
- `work/generation-log.json`은 계획과 실제 실행을 구분합니다.
- 영상 3개의 제작 계획까지 완료합니다. 실제 생성은 별도 실행 시험 요청 전까지 진행하지 않습니다.

**다음:** 07단계에서 샘플 성과 또는 같은 변형 ID로 연결된 실제 성과를 비교합니다.

## 07. 성과를 읽고 다음 규칙 수정

**입력:** `examples/performance.sample.csv`, `work/variants.json`, `work/creative-rules.md`.
샘플 CSV는 가상 성과입니다. 이번 실습에서 만든 광고를 실제 집행한 결과가 아닙니다.
계산을 마친 뒤 `examples/expected-performance.md`와 비교합니다.

**붙여 넣을 요청:** [피드백 프롬프트](../prompts/07-feedback.md)

```text
prompts/07-feedback.md를 읽고 7단계를 진행해줘.
샘플 성과의 기간, 통화, 비교 조건과 variant_id를 확인하고 work/performance.md에 분석해줘.
계산 후 examples/expected-performance.md와 비교하고 차이가 있으면 원인을 확인해줘.
다음 실험에서 바꿀 요소 하나를 제안하고 work/rule-changes.md에 변경 전후와 근거를 남겨줘.
work/creative-rules.md의 실험 가설을 갱신하되 브랜드 고정 기준은 유지해줘.
```

**완료 기준**

- `work/performance.md`에 계산한 지표, 비교 조건과 판단할 수 없는 항목이 있습니다.
- 비용이 0이거나 입력이 누락된 비율은 계산 불가로 표시합니다.
- `work/rule-changes.md`에 변경 전후, 근거, 다음 실험에서 확인할 내용이 있습니다.
- 샘플 결과를 보편적인 성공 규칙으로 단정하지 않습니다.

## 중간에 막히면

필수 work/ 입력이 없으면 01, 02 준비부터 확인하고 필요한 앞 단계를 순서대로 진행합니다.
03~06의 중간 결과는 준비한 자료로 새로 작성합니다. 실제 파일이 없다는 사실은 기록에 남깁니다.
영상은 연결 여부와 관계없이 프롬프트와 계획까지 저장하고 미생성 상태로 남깁니다. 실제 생성은 이번 준비 단계의 완료 조건이 아닙니다.
성과와 변형 ID가 맞지 않으면 먼저 대응 관계를 확인합니다. 임의로 다른 광고에 연결하지 않습니다.
마지막으로 출력 파일과 미완료 항목을 확인하면 이번 실습이 끝납니다.
